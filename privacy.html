Privacy

Rostrum has no telemetry, accounts or usage tracking. Optional update checks contact getrostrum.dev and GitHub; AppImage updates can also download a replacement executable. Optional crash reports go to Sentry. These choices are offered during first-time setup and can be changed in Settings → Updates and Settings → Privacy. Communication with OBS is separate and stays on your computer over localhost.

This page is a summary. The full details, including the exact fields a crash report may contain, are in docs/privacy.md in the source repository.

Your audio

  • Rostrum does not upload your audio. It mixes locally inside PipeWire; OBS or other recording apps handle any recording or streaming you choose.
  • Mic filters, noise removal included, also run inside PipeWire on your computer. RNNoise's model is part of the plugin, and no audio, level or transcript is stored or sent.
  • Check Mic keeps its 5-second recording in memory only and never writes it to disk. Only your headphones play it back.

Update checks and downloads

  • On by default, once a day: the first check runs 20 seconds after Rostrum starts, then at most every 24 hours while it runs.
  • It is a plain request for https://getrostrum.dev/releases/latest.json, which redirects to the file attached to the latest release on GitHub. So the check talks to getrostrum.dev and GitHub.
  • The request carries Rostrum's version in its User-Agent and nothing else about you: no cookies, no ID. Like any request, the servers see the IP address it comes from.
  • What happens next depends on how Rostrum was installed. The AppImage can download and replace itself after verifying the release checksum. A build from source shows a banner that links to what changed; rebuild it manually. Package installs are left to the package manager, and Flatpak installs do not check at all.
  • AppImage automatic installation is on by default when updates are enabled. Turn off automatic installation to wait for the Install action; turn off update checks to disable scheduled checks. Downloads come from GitHub and use the same no-cookie policy. Servers see the request’s IP address.
  • Use Settings → Updates to change these separate choices. Check Now also makes a request when you choose it.

Crash reports

  • Official builds include crash reporting. Ordinary source builds omit it and hide its settings; a custom build can explicitly enable it.
  • The default is to ask: the next time Rostrum starts after a crash, it offers to send the report, and Show the Report shows exactly what would be sent. You can also choose to always send, or never.
  • Reports go to Sentry (US region). Rostrum copies a fixed list of fields out of the crash: where it crashed, the signal, and the versions of Rostrum, the system, Qt, KDE Frameworks, PipeWire and WirePlumber. Everything else is dropped.
  • No names, file paths, device names, host name or IDs. No memory contents are captured. The server sees your IP address when receiving a report; Rostrum asks Sentry not to store it or look up a location from it.
  • There is no ping on launch, no session tracking and no breadcrumbs.

OBS

  • Rostrum talks to OBS through obs-websocket on 127.0.0.1 only. That traffic never leaves your computer.
  • Set Up OBS and Undo change OBS only when you press them.
  • While OBS runs, Rostrum can follow it to show LIVE and REC badges, go-live warnings and scene mapping. It only reads, and stores nothing apart from the scene mapping you choose. Turn background following off in Settings → OBS to connect only while the OBS page is open. Readiness also reads capture configuration; it does not change settings or test audience audio.

No network listener

Rostrum opens no network ports. The rostrum command and the D-Bus interface on your session bus are the only ways to control it from outside the window.

This website

getrostrum.dev is a set of static files hosted on Cloudflare Pages. It sets no cookies, runs no JavaScript, and has no analytics or trackers. Fonts, styles and images all come from this site; nothing is loaded from other servers. Cloudflare handles the requests to serve the pages.
